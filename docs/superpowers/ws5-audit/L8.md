## Findings

### QUESTIONABLE

#### Q1 — Z-relation "gotcha" task conflates inversional equivalence with Z-relation
- **Location:** `curriculumL8.ts`, module `l8u27m1`, task `l8u27m1t3` (lines ~396-399); reinforced by concept 3 (lines ~377-379) and the template hint in `templatesL8.ts` l8u27m2 ("Sets with the same interval vector are Z-related").
- **Type:** explanation / task
- **Severity:** questionable
- **What it says now:** Task t3 has the student compute ICV[0,1,4] = <1,0,1,1,0,0> and ICV[0,3,4] = <1,0,1,1,0,0>, then asks "Are they the same? What does this tell you about the two sets?" Concept 3 defines Z-relation as "two sets with identical ICVs but different prime forms." The template hint states flatly: "Sets with the same interval vector are Z-related."
- **The concern:** [0,1,4] and [0,3,4] are **inversions of each other** — they belong to the **same set class** (Forte 3-3), not a Z-related pair. (The module itself shows this in t2, where inv{0,1,4} normalizes to [0,3,4].) Inversionally-equivalent sets *always* share an ICV; that is not the Z-relation. A student who just learned "same ICV => Z-related" (template hint) and is then handed two same-ICV sets in t3 will naturally, and wrongly, conclude the pair is Z-related. In fact [0,1,4] and [0,3,4] reduce to the **same prime form** [0,1,4], so by the module's own definition ("different prime forms") they are *not* Z-related. The pedagogy walks the student into the exact misconception.
- **Correct version:** Either (a) pick a genuinely distinct ICV in t3 to contrast (so "are they the same?" answers *no*, illustrating that different set classes can have different vectors), or (b) keep [0,1,4]/[0,3,4] but make the teaching point explicit: "they share an ICV because they are inversions of one another — the same set class — which is *not* the Z-relation; Z-related sets share an ICV while being neither transpositions nor inversions of each other (smallest example: the 4-note pair 4-Z15 [0,1,4,6] and 4-Z29 [0,1,3,7])." Also soften the template hint to: "Sets with the same interval vector that are *not* related by transposition or inversion are Z-related."
- **Confidence:** high (the set-theory facts are deterministic; this is a framing defect, not a numeric error — hence "questionable" not "error").
- **Source/reasoning:** Forte, *The Structure of Atonal Music* (1973): 3-3 = [0,1,4]; Z-relation is defined only for sets not related by T_n/T_nI. Canonical smallest Z-pair: the all-interval tetrachords 4-Z15 / 4-Z29.

#### Q2 — Prime-form algorithm stated as universal; Forte/Rahn divergence not flagged
- **Location:** `curriculumL8.ts`, module `l8u27m1`, concept 2 (lines ~370-372): "Prime form transposes the normal order to start on 0, then compares with the inversion to select whichever is more tightly packed to the left." Also `templatesL8.ts` l8u27m2.
- **Type:** explanation
- **Severity:** questionable
- **What it says now:** Presents a single prime-form algorithm ("most tightly packed to the left") as *the* method, with no mention that two competing conventions exist.
- **The concern:** Two standard algorithms exist — **Forte's** (1973) and **Rahn's** (1980). They agree for the overwhelming majority of set classes but **diverge for a small handful of hexachords** (classic cases include 5-20, 6-31, 6-Z29, and the 6-Z17/6-Z43 and 6-Z19/6-Z44 situations), where the packing comparison resolves differently. The "more tightly packed to the left" wording is specifically the **Rahn** procedure. For every example actually used in L8 (all trichords) Forte and Rahn agree, so no worked answer is affected. But stating the algorithm as singular is incomplete for an advanced set-theory module and could mislead a student who later checks a hexachord against a Forte-convention table.
- **Correct version:** Add one clause: "Two conventions exist (Forte 1973 and Rahn 1980); they agree for all sets in this course and nearly all set classes, differing only for a handful of hexachords. The procedure shown follows Rahn, the more common modern choice." No worked example needs changing.
- **Confidence:** medium (the divergence is real and well-documented; whether it rises to "must-fix" for an awareness-level module is a judgment call — flagged for a human to decide).
- **Source/reasoning:** J. Rahn, *Basic Atonal Theory* (1980) vs A. Forte, *The Structure of Atonal Music* (1973); the Forte/Rahn discrepancy set is a standard graduate post-tonal topic (e.g., Straus, *Introduction to Post-Tonal Theory*).

### NITPICKS

#### N1 — "Augmentation ... effectively halving the tempo of the theme"
- **Location:** `curriculumL8.ts`, module `l8u25m2`, concept 3 (line ~92).
- **Type:** explanation
- **Severity:** nitpick
- **What it says now:** "Augmentation presents the subject in longer note values, effectively halving the tempo of the theme."
- **The concern:** Augmentation doubles durations; the *beat/tempo* is unchanged — what halves is the **rate at which the theme unfolds**. "Halving the tempo" is a defensible colloquialism but technically imprecise.
- **Correct version:** "...effectively making the theme unfold at half its original speed (note values typically doubled)."
- **Confidence:** high (imprecision is real; impact negligible).

#### N2 — "Quintal harmony ... (inversionally equivalent to fourths)"
- **Location:** `curriculumL8.ts`, module `l8u27m3`, concept 1 (line ~476).
- **Type:** explanation
- **Severity:** nitpick
- **What it says now:** Describes stacked fifths as "inversionally equivalent to fourths."
- **The concern:** A single P5 inverts to a P4 (true), but a *stack* of fifths is not voice-for-voice identical to a stack of fourths in register/spacing; the equivalence holds at the pitch-class / interval-class level (ic5). Correct under the pc-set reading the module teaches, and standard textbook shorthand — borderline, noted for completeness.
- **Correct version:** No change strictly required; if tightening, "...built from the same interval class as fourths (ic5)."
- **Confidence:** low (most texts use exactly this shorthand).

#### N3 — Glass additive-process illustration skips a step (4 -> 5 -> 6 -> 8)
- **Location:** `curriculumL8.ts`, module `l8u27m4`, concept 1 (line ~531): "a 4-note cell becomes 5, then 6, then 8."
- **Type:** explanation
- **Severity:** nitpick
- **What it says now:** Sequence 4->5->6->8 (omits 7).
- **The concern:** Additive process need not increment by one each time, so 4->5->6->8 is not *wrong*. But as an illustration of "adding notes incrementally," the silent jump from 6 to 8 reads as a typo and undercuts the "incremental" point in the same sentence.
- **Correct version:** Either 4->5->6->7, or keep 8 but say "...then 6, then (for instance) 8 — the increments need not be uniform."
- **Confidence:** medium (likely an unintentional skip).
