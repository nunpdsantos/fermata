**Scope:** Level 5 curriculum teaching text, hand-authored exercises, and generation templates.
**Audited (read-only):**
- `src/core/constants/curriculumL5.ts` — 14 modules across Units 15–17

**Headline:** The *teaching text* (curriculumL5.ts) and the *hand-authored exercises* (exercisesL5.ts) are theoretically sound — no factual errors found in the explanations, spellings, Roman-numeral analyses, pivot-chord analyses, mode-mixture spellings, or form definitions. **All 5 errors are concentrated in `templatesL5.ts`.** Four stem from one systemic defect: the template `moduleId`s for Units 16–17 are mapped to a **different module ordering** than the curriculum, so the generator attaches generated exercises to the WRONG module for 8 of 14 modules. The remaining template errors are prompt/answer-rule defects in three generative templates (`chord_build`/`scale_build`) where the generated answer does not satisfy the prompt for any parameter value.

## ERRORS

### E1 — Template/curriculum module misalignment for Units 16–17 (systemic)
- **Location:** `templatesL5.ts` L246–528 (moduleIds `l5u16m2`, `l5u16m3`, `l5u16m4`, `l5u16m5`, `l5u17m1`, `l5u17m2`, `l5u17m3`, `l5u17m4`)
- **Type:** template
- **Severity:** error
- **What it says now:** Template configs are keyed by `moduleId`. `exerciseGenerator.generateAllForLevel` builds exercises per `moduleId`, and `mergeExerciseMaps` merges them into the hand-authored map **by `moduleId`**. The template file assigns topics to module IDs using a *different* ordering than `curriculumL5.ts`:

  | moduleId | Curriculum topic (authoritative) | Hand-authored | **Template topic (generated)** |
  |---|---|---|---|
  | l5u16m2 | Modulation to Closely Related Keys | Closely Related Keys (ok) | **Direct/Phrase Modulation** (X) |
  | l5u16m3 | Direct/Common-Tone/Chromatic Mod | Direct/Common-Tone/Chromatic (ok) | **Common-Tone Modulation** (X) |
  | l5u16m4 | Mode Mixture — Borrowed Chords | Mode Mixture (ok) | **Closely Related Keys** (X) |
  | l5u16m5 | Picardy Third & Mixture in Minor | Picardy (ok) | **Chromatic Modulation** (X) |
  | l5u17m1 | Binary and Ternary Forms | Binary/Ternary (ok) | **Mode Mixture (Borrowed Chords)** (X) |
  | l5u17m2 | Song Forms & Large Forms | Song Forms (ok) | **Binary and Ternary Form** (X) |
  | l5u17m3 | Texture | Texture (ok) | **Rondo and Variations** (X) |
  | l5u17m4 | Guide Tone Lines | Guide Tone (ok) | **Sonata Form Introduction** (X) |

  (Unit 15, all 5 modules, and `l5u16m1` Pivot are correctly aligned across all three files.)
- **Why it's wrong / the concern:** A student studying "Binary and Ternary Forms" (`l5u17m1`) is served generated chord-building/MC exercises about **mode mixture / borrowed chords** (Ab major, Fm, Picardy third). "Texture" (`l5u17m3`) gets **rondo/variations** questions. "Guide Tone Lines" (`l5u17m4`) gets **sonata form** questions. The generated content is internally accurate theory but bolted onto the wrong lesson for 8 of 14 modules. Hand-authored + generated coexist in one module list, so each affected module mixes on-topic hand-authored items with off-topic generated items.
- **The correct version:** Re-key the Unit 16–17 template configs to the curriculum's module-to-topic mapping (e.g., "Closely Related Keys" block -> `l5u16m2` not `l5u16m4`; "Binary and Ternary" -> `l5u17m1` not `l5u17m2`; "Mode Mixture" -> `l5u16m4` not `l5u17m1`). Note the template set also has **no** template matching the curriculum's actual `l5u16m3` topic split and **no** template covering Song Forms or Sonata as the curriculum sequences them — a coverage gap that falls out of the same defect.
- **Confidence:** high
- **Source/reasoning:** Trace of `mergeExerciseMaps` (exerciseGenerator.ts L238–248) keying by `moduleId`; crosswalk of `id`/`moduleId`/comment labels across all three files. Hand-authored map is the alignment ground truth and matches the curriculum exactly.

### E2 — `l5u15m2` chord_build template: prompt asks for a secondary dominant but generates a dom7 on the key tonic (V7/IV of itself), with no target named
- **Location:** `templatesL5.ts` L60–70 (moduleId `l5u15m2`, first template)
- **Type:** template
- **Severity:** error
- **What it says now:** `promptTemplate: 'Build the secondary dominant chord that tonicizes the given target in {root} major.'` with `roots: ['C','G','D','F','A']`, `chordQualities: ['dominant7']`, `noteCounts: [4]`. In `fillTemplate`, `{root}` is replaced by the chord's own root (`config.root + config.rootAccidental`), and the generated answer is a dominant-7 chord built **on that same root**. So root `C` -> "...the given target in C major", answer = **C7**; root `G` -> "...in G major", answer = **G7**.
- **Why it's wrong / the concern:** (a) The prompt references "the given target," but no target appears in the rendered prompt — the student cannot know what to build. (b) Key and chord root are always the same letter, so every item is "dominant 7th on the tonic" = V7/IV of that key. For root `G` rendered "in G major," **G7 is the primary V7 of G major, not a secondary dominant** — calling it a "secondary dominant" is factually wrong. (c) The hint ("Build a dominant-quality chord a P5 above the target") contradicts the generated answer (a dom7 built *on* the named root, not a P5 above any target). The answer rule holds for no parameter value.
- **The correct version:** Either name an explicit target + fixed key and build the dom7 a P5 above it; or use a self-consistent prompt like "Build a {root} dominant 7th chord" and move V7/x labelling into the hint; or convert to multiple-choice pairing key + target + correct spelling (as the hand-authored `l5u15m2` items already do correctly).
- **Confidence:** high
- **Source/reasoning:** Trace of `buildConfig` chord_build branch (exerciseGenerator.ts L90–105) and `fillTemplate` chord_build branch (L161–164). The dom7 on a key's own tonic is V7/IV, never "the secondary dominant tonicizing a given target."

### E3 — `l5u16m4` scale_build template ("Closely Related Keys"): builds the {root} major scale itself, which is NOT a key closely related *to* {root}
- **Location:** `templatesL5.ts` L309–319 (moduleId `l5u16m4`, first template)
- **Type:** template
- **Severity:** error
- **What it says now:** `promptTemplate: 'Build the major scale of a closely related key to {root} major.'` with `roots: ['G','F','D','A','E','C']`, `scaleTypes: ['major']`, `noteCounts: [7]`. `{root}` is filled with the scale's own root; generated answer = **{root} major scale**. E.g. root `G` -> "Build the major scale of a closely related key to G major", correct answer = **G major** itself.
- **Why it's wrong / the concern:** A key is not "closely related" to itself; it *is* itself. The generated answer (the {root} major scale) never satisfies the prompt (a *different*, closely related key). Wrong for all six values. The template system binds `{root}` to the build target, so prompt and answer always reference the same key. (Also lands under the wrong module per E1 — topic belongs at `l5u16m2`.)
- **The correct version:** `scale_build` cannot reference a key distinct from the scale built, so this concept is not expressible as single-root scale_build. Use multiple-choice (the second template in this block already does this correctly), or drop the scale_build template. If retained, the prompt must be "Build the {root} major scale" with no "closely related" framing.
- **Confidence:** high
- **Source/reasoning:** Trace of `buildConfig` scale_build branch (exerciseGenerator.ts L72–88) and `fillTemplate` scale_build branch (L157–159). Definitional: closely related keys differ by >=1 accidental and exclude the home key.

### E4 — `l5u17m1` chord_build template ("Mode Mixture"): labels the borrowed chord's root as the *key*, producing incoherent prompts ("borrowed chord ... in Ab major", "... in Cb major")
- **Location:** `templatesL5.ts` L383–393 (moduleId `l5u17m1`, first template)
- **Type:** template
- **Severity:** error
- **What it says now:** `promptTemplate: 'Build the borrowed chord from the parallel minor in {root} major.'` and `hintTemplate: '... In {root} major, lower the 3rd, 6th, or 7th degree.'` with `roots: ['A','E','D','G','C','F']`, `accidentals: ['b','b','b','b','b','']`, `chordQualities: ['major']`, `noteCounts: [3]`. Effective roots: **Ab, Eb, Db, Gb, Cb, F** major triads. `{root}` is filled with chord root + accidental, so prompts render "...in **Ab** major", "...in **Eb** major", "...in **Cb** major".
- **Why it's wrong / the concern:** Intended pedagogy is borrowed chords *within C major* (Ab=bVI, Eb=bIII, Bb=bVII, Fm=iv). Filling `{root}` with the borrowed chord's own root mislabels that root as the **key**: "Build the borrowed chord from the parallel minor in Ab major" is incoherent — Ab is the *chord*, C is the *key*. "Cb major" (5th value) is a needlessly exotic, near-nonsensical key reference. The hint inherits the defect ("In Ab major, lower the 3rd..."). The chord built (e.g. Gb major for root `Gb`) is not a standard parallel-minor borrowing in any key the prompt names. Wrong for every value. (Also lands under the wrong module per E1 — belongs at `l5u16m4`.)
- **The correct version:** Fix the key reference to a constant (e.g. always "C major") and choose roots that are genuine parallel-minor borrowings in that fixed key. Since `{root}` is bound to the build target, cleanest fix is multiple-choice (the second template in this block — "The bVI chord in C major is Ab major" — is correct), or a chord_build prompt without naming a key, e.g. "Build Ab major (the bVI borrowed chord)".
- **Confidence:** high
- **Source/reasoning:** Trace of `fillTemplate` chord_build branch (exerciseGenerator.ts L161–164: `{root}` = root+accidental). A borrowed chord is named relative to the prevailing key (bVI of C), not relative to its own root as a key.

## QUESTIONABLE (needs human verification — no fix asserted)

### Q1 — Curriculum claim that vii°7/x is "more common in minor keys" and viiø7/x "more common in major keys"
- **Location:** `curriculumL5.ts` L142 (module `l5u15m3`, "Fully Diminished vs. Half-Diminished")
- **Type:** explanation
- **Severity:** questionable
- **What it says now:** "viio7/X (fully diminished seventh) is more intense and more common in minor keys. ... viiø7/X (half-diminished seventh) is less intense and more common in major keys."
- **The concern:** Textbooks differ. The standard claim (Kostka/Payne, *Tonal Harmony*) is that the **applied/secondary leading-tone seventh in major** is frequently **fully diminished**, and that the half-diminished applied seventh is the *diatonic* leading-tone seventh of major. The blanket "half-diminished is more common in major" is defensible for the *diatonic* viiø7 of the major tonic but is a contested generalization for *secondary* leading-tone chords, where vii°7/x (fully diminished) is very common in major too. The enharmonic-pivot point (L142–143) is correct.
- **Suggested correct version:** **Needs human verification.** Likely soften to: "In major, the diatonic vii°7 of the tonic is half-diminished, but **secondary** leading-tone sevenths are often fully diminished regardless of mode." Do not assert without a chosen authority.
- **Confidence:** medium
- **Source/reasoning:** Kostka/Payne; Aldwell/Schachter. Not false so much as over-broad where reputable sources differ.

### Q2 — "bVII borrowed from the parallel minor" (L5 text) vs. "bVII borrowed from Mixolydian" (Explore data)
- **Location:** `curriculumL5.ts` L476/L483/L492 (module `l5u16m4`) vs. `progressionPatterns.ts` L124–129 (`I-bVII-IV`: "borrowed chord from Mixolydian")
- **Type:** explanation
- **Severity:** questionable
- **What it says now:** L5 mode-mixture attributes bVII (Bb in C) to the **parallel minor**; the Explore progression catalog attributes the same bVII to **Mixolydian**.
- **The concern:** Both are valid sources for bVII (it occurs in natural minor, Mixolydian, and Dorian). Within the mode-mixture lesson the "parallel minor" framing is internally consistent and standard. Cross-surface labeling inconsistency, not a theory error.
- **Suggested correct version:** **Needs human/editorial decision.** Optionally note bVII is shared with Mixolydian. No correction asserted.
- **Confidence:** medium
- **Source/reasoning:** Bb-D-F is diatonic to C natural minor, C Mixolydian, and C Dorian.

### N3 — `l5u17m4e2` hint phrasing muddles guide-tone voice-leading direction (answer itself is correct)
- **Location:** `exercisesL5.ts` L719 (hint for `l5u17m4e2`)
- **Type:** exercise · **Severity:** nitpick
- **What it says now:** "G7: the C holds as common tone becoming the 7th of the chord, while F drops to B (3rd)." In Dm7->G7, the **7th of Dm7 is C**, which resolves **down to B (3rd of G7)**; the **3rd of Dm7 is F**, which is **held as the 7th of G7**. The hint inverts which tone holds and which moves. The *answer choice* (L713: "F-C in Dm7, F-B in G7, E-B in Cmaj7") is **correct**; only the hint prose is wrong.
- **Concern:** Minor; correct answer unaffected; the concept text in `curriculumL5.ts` L762 states the voice leading correctly.
- **Confidence:** high · **Source:** Guide-tone voice leading; cross-checked against the module's own (correct) concept text.
