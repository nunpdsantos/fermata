# Level 9 (Ear Training & Aural Skills) — Music-Theory Correctness Audit

**Scope:** Read-only correctness audit of Fermata's Level 9 curriculum content against authoritative music theory.

**Files audited**
- Teaching text: `src/core/constants/curriculumL9.ts` — 15 modules across 3 units (u30, u31, u32).
- Hand-authored exercises: `src/data/exercises/exercisesL9.ts` — 50 exercises.
- Generation templates: `src/data/exercises/templatesL9.ts` — 14 module template-configs (l9u32m5 intentionally has none), 18 individual templates.

**Cross-referenced (authoritative engine constants):** `src/core/constants/intervals.ts`, `chords.ts`, `scales.ts`, `modes.ts`, `glossary.ts`; validation semantics in `src/components/learn/exercises/validateExercise.ts`; generation semantics in `src/data/exercises/exerciseGenerator.ts`.

**Validation semantics established (affects how the "answer key" is judged):**
- `interval_id` is validated **by semitone count only** (the answer is an integer). The interval *name* shown in feedback comes from `INTERVAL_LABELS[semitones]` in `chords.ts`, NOT from the prompt/hint text. This is the source of Finding E1.
- `scale_build` / `chord_build` are validated **by pitch-class set** — spelling/enharmonics do not affect correctness, only the set of pitch classes. All root-ranging build templates are therefore correctness-safe regardless of spelling.
- `scale_degree_id` is validated by the `correctDegree` integer directly; the `note` field is an unused placeholder.
- Template `accidentals[]` pairs **positionally** with `roots[]` (shared index `idx` in `exerciseGenerator.ts`). All L9 templates have length-matched `roots`/`accidentals` arrays (verified) — no positional-spelling bugs.

## ERRORS

### E1. "Minor 6th" interval items return "Augmented 5th" as the correct-answer feedback
- **Location:** `exercisesL9.ts` l9u30m4e1 (prompt + hint, "minor 6th. C to Ab"); `templatesL9.ts` l9u30m4 hint ("m6=8 (bittersweet)") and l9u30m3 / l9u32m2 / l9u32m3 wherever 8 semitones can be generated; `curriculumL9.ts` l9u30m4 concept text. Root cause: `chords.ts` `INTERVAL_LABELS[8] = 'Augmented 5th'` and `INTERVAL_SHORT_LABELS[8] = '#5'`.
- **Type:** exercise / explanation (cross-file engine interaction)
- **Severity:** error
- **What it says now:** The content consistently and correctly calls 8 semitones a "minor 6th" (C→Ab). But `validateIntervalId` builds its feedback string via `getIntervalLabel(8)` → `INTERVAL_LABELS[8]` → **"Augmented 5th"**. So a learner who is told "identify this minor 6th," answers 8 semitones, and is told *"Correct! That's an Augmented 5th"* — or, if wrong, *"That was an Augmented 5th, not a …"*.
- **Why it's a problem:** A6/m6 are enharmonic (both 8 semitones), but in an interval-recognition module that explicitly teaches and names the **minor 6th**, surfacing "Augmented 5th" as the canonical answer is pedagogically wrong and directly contradicts the prompt/hint the learner just read. The augmented 5th is far rarer melodically; in every L9 context here the intended interval is the minor 6th.
- **Correct version:** For the 8-semitone slot, feedback should read "Minor 6th." This is an engine-label issue (`INTERVAL_LABELS[8]`), but it is load-bearing for L9 because L9 is the only level that drills bare ascending/descending m6 by ear. Note the asymmetry: the engine already prefers the 6th/7th naming for 9 ('Major 6th'), 10 ('Minor 7th'), 11 ('Major 7th'), but the *augmented-5th* naming for 8 — internally inconsistent. (This is an engine constant; per audit scope it is reported, not edited.)
- **Confidence:** high (computed; `INTERVAL_LABELS[8]='Augmented 5th'` verified directly; validation path traced in `validateExercise.ts`).
- **Source/reasoning:** 8 semitones = minor 6th (= augmented 5th enharmonically). Standard interval naming in an ascending-interval-ID context uses minor 6th.

### E2. Harmonic-interval template hint omits the perfect 5th from its consonance list
- **Location:** `templatesL9.ts` l9u30m5 (Harmonic Intervals), the single `interval_id` template's `hintTemplate`.
- **Type:** template
- **Severity:** error
- **What it says now:** `intervals: [3, 4, 5, 7, 8, 9, 12]` are playable, but the hint says: *"Consonances (3, 4, 5, 8, 9, 12) blend smoothly. Dissonances (1, 2, 6, 10, 11) create tension."* The value **7 (perfect 5th) is in the played set but appears in neither list.**
- **Why it's wrong:** The perfect 5th is the most consonant interval after the unison and octave. When the generator produces a P5 harmonic interval (7 semitones), the hint's classification gives the learner no guidance — and by omission implies it is neither consonant nor dissonant. It is also internally inconsistent to list the perfect 4th (5) as a consonance while dropping the perfect 5th (7). (Listing m6=8 as a consonance is defensible — it is an imperfect consonance — so 8 is not the problem; 7 is.)
- **Correct version:** Consonance list should be `(3, 4, 5, 7, 8, 9, 12)` (add 7). Dissonances `(1, 2, 6, 10, 11)` are correct as written.
- **Confidence:** high (the played `intervals` array and the hint text were compared directly; P5 consonance is canon).
- **Source/reasoning:** Standard consonance taxonomy: perfect consonances P1/P5/P8 (+P4 contextually), imperfect consonances m3/M3/m6/M6, dissonances m2/M2/TT/m7/M7.

### Q5. Movable-do vs fixed-do framing (opinion stated as fact)
- **Location:** `curriculumL9.ts` l9u32m4 concept "Movable-Do Solfege."
- **Type:** explanation — **severity:** questionable (convention-dependent, stated for transparency).
- **What it says:** "This is the Kodaly/Berklee approach… Fixed-do (where do always equals C) is used in France and Italy but does not train functional hearing the same way."
- **Concern:** The L9 content uses **movable-do** throughout (correctly and consistently). The factual core (movable-do = do-on-tonic) is correct canon. But (a) "does not train functional hearing the same way" is a defensible pedagogical *position*, not a neutral fact; reputable fixed-do pedagogues dispute it. (b) Lumping "Kodály/Berklee" is a simplification (Kodály traditionally uses la-based minor; Berklee uses do-based with numbers). Recommend softening to opinion or attributing it.
- **Confidence:** medium.

### Q6. Do-based vs la-based minor solfège — system is mixed but each instance is internally correct
- **Location:** `curriculumL9.ts` l9u32m4 concept "Chromatic Solfege for Minor Keys" (uses **do-based** minor: `do-re-me-fa-sol-le-te-do`), with a parenthetical la-based gloss (`la-ti-do-re-mi-fa-sol`); exercise l9u32m4e2; unit u32 milestone label `do-re-me-fa-sol-le-ti-do`.
- **Type:** explanation — **severity:** questionable (convention note, not an error).
- **Verification done:** do-based natural minor `do-re-me-fa-sol-le-te-do` is correct (b3=me, b6=le, b7=te). The harmonic-minor milestone label `do-re-me-fa-sol-le-ti-do` correctly raises only the 7th (te→ti). The la-based parenthetical for A natural minor (`la-ti-do-re-mi-fa-sol`) is correct. So every instance is right **within its own system.**
- **Concern:** The content commits to **do-based minor** (a legitimate choice) but offers a la-based gloss in one spot. Mixing the two systems in one module can confuse learners. Recommend a human pick one convention and state it explicitly. Not a factual error.
- **Confidence:** high (the syllable mappings were verified note-by-note); flagged only because the convention choice is mixed.

### Q7. Harmonic-interval template hint lists m6 (8) as a consonance
- **Location:** `templatesL9.ts` l9u30m5 hint (same hint as E2).
- **Type:** template — **severity:** questionable.
- **Concern:** Independent of the E2 P5 omission, classifying m6 (8) as a "consonance that blends smoothly" is defensible (imperfect consonance, the inversion of M3) but some textbooks treat the 6th as contextually dissonant. Lower priority than E2; a human may wish to footnote it. Not asserted wrong.
- **Confidence:** medium.

## NITPICKS

### N1. "Smallest interval in Western music" phrasing
- **Location:** `exercisesL9.ts` l9u30m3e1 prompt: the minor 2nd is "the smallest interval in Western music."
- **Type:** explanation — **severity:** nitpick.
- **Concern:** The semitone (m2) is the smallest interval in **12-tone equal temperament / standard Western practice**, which is clearly the intended scope. Strictly, Western microtonal music and just-intonation commas are smaller. Acceptable for this curriculum; flagged only for pedantic accuracy.
- **Confidence:** high.

### N2. l9u30m2 interval template prompt says "Is it major or minor?" for an interval, in a chord-framed module
- **Location:** `templatesL9.ts` l9u30m2, `interval_id` template, `intervals: [3, 4]`.
- **Type:** template — **severity:** nitpick.
- **Concern:** The template plays a m3 (3) or M3 (4) and asks "Is it major or minor?" — fine for drilling the third's quality. But the module is titled "Major vs Minor *Recognition*" and frames things around **chords**; an interval-only m3/M3 drill is a slight mismatch with the chord-focused concept text. Pedagogically reasonable; no theoretical error.
- **Confidence:** high.

### N3. Compound-interval coverage inconsistency (13th)
- **Location:** `curriculumL9.ts` l9u30m5 concept "Compound Intervals" (lists 9th/10th/11th/13th) vs u30 milestone `skillsSummary` ("compound intervals (9ths, 10ths, 11ths)").
- **Type:** explanation — **severity:** nitpick.
- **Concern:** Minor inconsistency in which compounds are enumerated (13th appears in the concept but not the milestone summary). All stated identities are correct (9th=8ve+2nd, 10th=8ve+3rd, 11th=8ve+4th, 13th=8ve+6th). Cosmetic.
- **Confidence:** high.

### N4. l9u30m5 framed as "harmonic intervals," but the `interval_id` type is a single semitone-distance question
- **Location:** `exercisesL9.ts` l9u30m5e1/e2 and `templatesL9.ts` l9u30m5 — prompts say "These two notes sound simultaneously."
- **Type:** exercise/template — **severity:** nitpick (engine limitation, not a theory error).
- **Concern:** Whether the app actually plays the two notes *simultaneously* vs. melodically is an audio-engine/UI concern outside the data files. The theory labeling (P4=5, M3=4, etc.) is correct. Noting only that the "simultaneously" promise depends on playback implementation, which this audit did not execute (see limitations).
- **Confidence:** medium.

## Coverage & limitations

- **Audited:** all 15 modules' teaching text, all 50 hand-authored exercises, and all template-configs in the three target files. Cross-checked every semitone/spelling claim against `intervals.ts`, `chords.ts`, `scales.ts`, `modes.ts` by recomputation (scratch scripts; read-only, nothing written to source).
- **Validation path traced:** confirmed via `validateExercise.ts` that `interval_id` answers are semitone-based and that feedback labels come from `INTERVAL_LABELS` — this is what surfaced E1. Confirmed `scale_build`/`chord_build` are pitch-class-set based (spelling-agnostic for correctness) and `scale_degree_id` is integer-degree based.
- **Generation path traced:** confirmed in `exerciseGenerator.ts` that `accidentals[idx]` pairs positionally with `roots[idx]`, then checked every L9 template for array-length parity (all pass).
- **NOT executed (out of scope for a static content audit):** actual audio playback. Whether the app truly plays an interval *ascending/descending*, *simultaneously* (harmonic) vs. sequentially, or plays a *scale* vs. a *chord* for a given exercise depends on the audio engine and exercise-runner UI, which were not run. The "what would actually sound" check here is therefore against the **data** (config semitones/pitch classes), not against rendered audio. If the runner's interval playback direction or simultaneity diverges from the prompt wording, that is a separate (UI) bug class. CLAUDE.md notes engine support for L9 is "PARTIAL" (audio works, dedicated quiz UI not built) for u30/u31 and "comingSoon" for u32.
- **Reference-song mnemonics (Q1–Q4):** flagged, not corrected. Per the audit's discipline, I did not assert any song mnemonic is wrong; I lack confident knowledge of each song's literal opening interval, and a wrong "correction" would be worse than a flag. A human (or a web-verified pass) should confirm each opening interval.
- **i18n overlays (pt/es) for L9 were NOT audited** — only the English source. Translation files could re-introduce or mask any of these issues.
- **Confidence convention:** "high" = computed from formulas/canon; "medium" = canon-adjacent but with a convention or implementation dependency; "low" = cultural/mnemonic claim not derivable from theory.
