**Scope:** L1 teaching text, hand-authored exercises, and generation templates, plus the
core engine functions L1 actually invokes at validation/generation time.

**Headline:** The hand-authored teaching text and exercise answer keys for L1 are
theoretically sound. Every scale-build and chord-build template was machine-verified to
produce correctly-spelled answers for ALL parameter values in its range (no false answer
key found in any build template). All interval labels used in L1 are canonical. The one
ERROR is a generation defect, not a wrong fact: the generated scale_degree_id exercises
(module l1u3m1) are unanswerable as posed because the note to be identified is never shown
to the user, while the "correct" degree is chosen at random.

## Findings

### ERROR-1 — Generated scale_degree_id exercises are unanswerable; the graded answer is arbitrary
- **Location (template):** src/data/exercises/templatesL1.ts lines 255-265 (module l1u3m1, 2nd template).
- **Location (generator):** src/data/exercises/exerciseGenerator.ts lines 115-134 (buildConfig scale_degree_id branch) and lines 165-169 (fillTemplate scale_degree_id branch).
- **Type:** template (generation) / exercise answer key.
- **Severity:** error. **Confidence:** high (confirmed in code, not inferred).
- **What it says now:** The template prompt is "In the {root} {scaleType} scale, identify the scale degree of the given note." The generator builds a config with correctDegree = pick([1..7]) chosen at random, and sets note: roots[idx] with the inline comment "// placeholder — overridden below". It is never overridden. fillTemplate for scale_degree_id only substitutes {root}, {scaleType}, {degree} — there is no {note} token in the prompt, and ExercisePrompt.tsx (lines 33-66) renders staff notation only for note_id and interval_id, returning null for scale_degree_id. So the user sees "identify the scale degree of the given note" with no note given, and must pick a degree; validation (validateScaleDegreeId) compares the pick to a correctDegree that bears no relationship to any displayed note.
- **Why it's wrong:** The exercise cannot be answered from the information presented; the "correct answer" is undiscoverable and effectively random. This mis-teaches by presenting an unsolvable task as if it had a determinate answer.
- **Correct version:** The prompt must state the note (e.g. resolve degree -> actual scale note via buildScale(root, scaleType)[degree-1] and inject it, or restate as "what note is degree N of {root} {scaleType}?"), OR the generator must compute and display the note for the chosen degree. As written, the template should either be fixed or removed. (Note: the hand-authored scale_degree_id exercises in exercisesL1.ts — l1u3m1e_deg1..4 — are correct: they name the note in the prompt, e.g. "what degree is the note E?", and their correctDegree values 3/5/4/3 are right.)
- **Source/reasoning:** Cross-read of generator, fillTemplate, ExercisePrompt, and validateScaleDegreeId. The C-major / G-major degree facts the hand-authored items assert (E=3, G=5, F=4 in C; B=3 in G) are canon.

### QUESTIONABLE-1 — interval_id prompts say "count letter names," but grading is by semitone only; root letter is ignored
- **Location:** src/data/exercises/templatesL1.ts lines 316-326 (module l1u3m3 template; ranges roots C,D,E,F,G,A x semitones 2,3,4,5,7); also the hand-authored interval items l1u3m3e1..3 and l1u1m3e1..3. Validation: validateExercise.ts validateIntervalId (lines 156-171) + INTERVAL_LABELS (chords.ts 416-440).
- **Type:** template / exercise.
- **Severity:** questionable. **Confidence:** high (mechanism), medium (whether it can mis-grade in L1).
- **Concern:** The prompt instructs the learner to "count both letter names and semitones," but the answer is keyed purely to targetSemitones; the interval number/quality label is taken from INTERVAL_LABELS[semitones] (the default simple spelling) and the root letter is never used. For every root and every semitone value L1 actually ranges over (1,2,3,4,5,7), the default label is the correct generic name (m2, M2, m3, M3, P4, P5), so no L1 instance is mis-graded. The concern is (a) pedagogical mismatch (it asks for letter-counting but doesn't check it), and (b) latent fragility: INTERVAL_LABELS[6]="Tritone" and INTERVAL_LABELS[8]="Augmented 5th" are not interval-number answers, so if the interval range were ever widened to include 6 or 8 the label would stop matching a "count the letters" answer. L1 never hits 6 or 8, so this is latent, not active.
- **Suggested framing:** Either drop the "count letter names" instruction from the generated interval prompts, or have the generator carry an explicit interval-number answer. Not an error for L1 as shipped.
- **Source/reasoning:** Verified the full L1 interval semitone set is {1,2,3,4,5,7}; checked each against INTERVAL_LABELS and SEMITONES_TO_INTERVAL.

### QUESTIONABLE-2 — note_id treble template can place a note on a ledger line while saying "on the treble clef staff"
- **Location:** src/data/exercises/templatesL1.ts lines 18-27 (module l1u1m1, note_id template): roots C..B, octaves [4, 5], prompt "Identify the note {note} on the treble clef staff."
- **Type:** template.
- **Severity:** questionable. **Confidence:** high.
- **Concern:** With octave 4 included, C4 (middle C) and D4 fall below the 5-line treble staff (on/below a ledger line), so "on the treble clef staff" is imprecise for those instances. The answer (note name) is still correct — validateNoteId ignores octave entirely — so this is wording, not a wrong key. Module l1u1m1 is explicitly "The Staff and Clefs" (ledger lines are introduced in l1u1m2), so showing a ledger-line note here is slightly out of sequence.
- **Suggested framing:** Restrict this template's octaves to staff range, or soften the prompt to "on the treble staff (or its ledger lines)." Low impact.

### QUESTIONABLE-3 — Generated scale_build / chord_build prompts hard-code the note count in the prompt text rather than deriving it
- **Location:** src/data/exercises/templatesL1.ts lines 245-254 (l1u3m1 scale prompt "Select all 7 notes...") and 336-345 / 347-357 (l1u3m4 chord "Select the root, major 3rd...and perfect 5th"). Validation: validateScaleBuild/validateChordBuild compare pitch-class sets.
- **Type:** template.
- **Severity:** questionable (robustness note). **Confidence:** high.
- **Concern:** The answer is validated by exact pitch-class set equality against buildScale/buildChord, which is correct and was machine-verified for every L1 root (see Coverage). The "7 notes" / 3-note wording is hard-coded in the prompt string rather than derived, so it is only correct because L1 fixes scaleTypes:['major'] and chordQualities:['major'] with noteCounts:[7]/[3]. Within L1 this is fully correct; flagging only because the prompt text would silently desync if the param ranges were broadened. No action needed for L1.

### NITPICKS (imprecise wording, not wrong)

- **NITPICK-1 — curriculumL1.ts line 133 (module l1u1m4, "The 12 Notes"):** the chromatic ascent is given entirely with sharps (C, C#, D, D#, ...). That is the conventional ascending-sharp spelling and is correct; just note it silently picks one enharmonic convention. The next module text and exercises do teach flats, so no contradiction. No change required.
- **NITPICK-2 — curriculumL1.ts line 98 (module l1u1m3, "Sharps, Flats, and Naturals"):** "Between most natural notes there's a note in between" — informal but accurate (5 of the 7 natural-to-next-natural gaps contain a black key; E-F and B-C do not). Fine.
- **NITPICK-3 — exercisesL1.ts line 525 (l1u3m2e3 hint):** "Sharps accumulate in order: F#, C#, G#, D#, A#, E#, B#." Correct canon (order of sharps F-C-G-D-A-E-B; the 6th/7th sharps E#, B# appear in F# / C# major). Accurate but lists all seven when the item only concerns D major's first two; harmless.
- **NITPICK-4 — Shared UI constant INTERVAL_LABELS[8] = 'Augmented 5th' (chords.ts line 424) and the "#5 = Augmented 5th" tooltips (educationalContent.ts):** In isolation, 8 semitones is canonically a minor 6th; "augmented 5th" is the chord-context spelling. NOT used anywhere in L1 (L1 intervals only reach semitones 1-7), so out of scope for L1 correctness — recorded only so a later L2+ audit (where 8-semitone intervals appear) can decide whether the generic interval-ID label should be "Minor 6th." Flag, do not "fix" from an L1 standpoint.

## Coverage & limitations (what was NOT fully verified)

- **PRNG-seeded generated instances:** I verified the RULES (every root x every param value a template ranges over) by reproducing the engine's spelling logic and enumerating the full parameter space for scale-build, chord-build, and interval-id. I did NOT execute the real generateExercises with its actual hashString(moduleId) seed to enumerate the specific ~55 instances that ship; instead I proved the generators are correct over their entire range, which is strictly stronger for the build/interval types. For multiple_choice templates the answer is fixed in the data (a literal correct:true choice) and was read directly. ERROR-1 (scale_degree_id) holds for EVERY seed because the note is never shown regardless of which degree is picked.
- **Audio playback correctness** (the synthesized pitch for ear-training and interval playback in ExerciseRunner) was read but not run/heard; pitch-class math there matches ExercisePrompt's staff math, but I did not verify actual frequencies aurally.
- **Staff-notation rendering** (VexFlow) was reasoned about from ExercisePrompt (clef selection, spelling passed through) but not rendered; I did not confirm pixel-level placement.
- **PT / ES content overlays** (src/i18n/content/pt|es/curriculumL1|exercisesL1|templatesL1) were OUT OF SCOPE and not audited. They could introduce translation-specific theory errors (e.g. a mistranslated interval/scale term) independent of the English source. Recommend a separate overlay pass; note musicTerms.ts dictionaries drive generated-prompt term translation and were not checked.
- **glossary.ts / educationalContent.ts:** these power Explore-view tooltips, not L1 curriculum, and L1 modules do not reference them. Audited only incidentally (see NITPICK-4); not exhaustively verified for L1 since L1 does not use them.
- **Cross-module prerequisite ordering** and objectives/milestone/completionContent prose were read for factual claims (all correct) but not evaluated for pedagogy/sequencing beyond the one ledger-line-before-introduction note in QUESTIONABLE-2.
