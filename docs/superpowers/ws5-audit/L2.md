# Fermata Level 2 (Expanding Fundamentals) — Music-Theory Correctness Audit

**Scope:** Level 2 curriculum content only. Read-only audit; no source files modified.
**Auditor frame:** Theoretical correctness against established textbook canon (key signatures, scale degrees, the three minor scales, compound meter, triad qualities, inversions/figured bass, diatonic harmony). Style and pedagogy preferences excluded.

## Coverage

| Artifact | Reviewed |
|---|---|
| Modules (curriculumL2.ts: titles, subtitles, objectives, concept explanations, tasks, milestones) | 12 (l2u4m1-2, l2u5m1-3, l2u6m1-2, l2u7m1-5) |
| Hand-authored exercises (exercisesL2.ts) | 47 |
| Generation templates (templatesL2.ts: 12 ModuleTemplateConfig / 16 template objects) | 12 configs |

**Method.** Type shapes read from `curriculum.ts` / `exercise.ts`. The runtime validator (`src/components/learn/exercises/validateExercise.ts`) and the engine constants (`scales.ts`, `chords.ts`, `intervals.ts`, `notes.ts`) were read in full. For every scale/chord/interval that an L2 exercise or template actually exercises, the engine output (`buildScale`, `buildChord`, `buildInterval`, `INTERVAL_LABELS`, `SEMITONES_TO_INTERVAL`) was computed and compared against (a) the prompt/hint text and (b) canonical theory. The two existing audit scripts were run as a baseline (`verify-engine.ts`: 23 critical findings, all in exotic scales on theoretical roots that L2 never uses; `verify-exercises.ts`: 0 findings). **Important limitation of those scripts:** `verify-exercises.ts` derives the "correct" answer FROM the config and feeds it back to the validator — it is structurally blind to (i) wrong claims in prompt/hint *text*, and (ii) cases where the validator's accepted label is itself theoretically wrong. The human findings below target exactly that gap.

## Summary of findings

| Severity | Count |

Headline: the engine's per-key scale and triad spellings for everything L2 teaches are **correct** (all major keys D/A/E/F/B/G + Bb; all natural/harmonic/melodic minors on the templated roots; all four triad qualities; the C-major diatonic set). ## ERRORS

### E1. Interval at 8 semitones is labelled "Augmented 5th" inside modules that teach it as a Minor 6th
- **Location:** `templatesL2.ts` l2u7m1 (interval template, `intervals: [1,2,3,4,5,7,8,9,10,11,12]`) and l2u7m2 (`intervals: [1,3,4,6,8,10,11]`); root cause in `src/core/constants/chords.ts` `INTERVAL_LABELS[8] = 'Augmented 5th'` consumed by `validateExercise.ts` `getIntervalLabel` and by `exerciseHelpers.ts` `generateIntervalChoices`.
- **Type:** template (+ engine constant it depends on)
- **Severity:** error
- **What it says now:** When the generator draws `targetSemitones = 8`, the interval-ID multiple-choice presents "Augmented 5th" as the (only) correct choice and the feedback string reads "Augmented 5th." Module l2u7m1 is titled *"Interval Quality: Perfect, Major, Minor"* and its stated objective is to "Classify major and minor intervals: 2nd, 3rd, 6th, 7th." The natural target name at 8 semitones in that frame is **Minor 6th**.
- **Why it's wrong / the concern:** 8 semitones spans a minor 6th in the perfect/major/minor system the module teaches; "augmented 5th" is the *enharmonic* spelling that only applies when the upper note is written as a raised 5 (e.g. C->G#), which is not what an interval-quality lesson on minor 6ths intends. The codebase even contradicts itself: `SEMITONES_TO_INTERVAL[8]` returns `{ quality: 'minor', number: 6 }`, while `INTERVAL_LABELS[8]` returns `'Augmented 5th'`. Because validation is by semitone count only, the answer is not "rejected," but the **label the student sees and must select is the wrong quality name** for this module, and the m6 reading is not offered as a choice. This fires every time 8 is drawn (l2u7m2 explicitly ranges over 8; l2u7m1 includes it).
- **Correct version:** For an interval-quality module, the canonical label at 8 semitones is "Minor 6th." (The reusable fix is for `INTERVAL_LABELS[8]` to read "Minor 6th" to agree with `SEMITONES_TO_INTERVAL`, or for these L2 interval templates to drop `8` from their range. A truly spelling-aware label would require passing the upper-note spelling into the validator, which the current semitone-only design does not do.) **Recommendation only; not applied in this read-only audit.**
- **Confidence:** high (label vs module objective is unambiguous; internal contradiction with `SEMITONES_TO_INTERVAL[8]` is dispositive).
- **Source/reasoning:** Standard interval taxonomy (8 semitones = minor 6th; augmented 5th is the enharmonic respelling). Engine output verified: `C +8 => G#`, `D +8 => A#`, `E +8 => C`, all labelled "Augmented 5th."

## QUESTIONABLE (needs human verification — not asserted as fixes)

### Q1. Generated triads can require double-sharps not selectable as such on the instrument (B augmented -> B D# F##)
- **Location:** `templatesL2.ts` l2u7m3 (four-triad template: roots `[C,D,E,F,G,A,B]` x qualities `[major,minor,diminished,augmented]`, noteCount 3).
- **Type:** template
- **Severity:** questionable
- **What it says now:** Hint: "Augmented = root + M3(4) + aug5(8)." For root B, the engine correctly spells B augmented as **B, D#, F##** (pitch classes 11, 3, 7).
- **Concern:** The *pitch classes* and the *spelling* are both theoretically correct (F## keeps one-letter-per-chord-tone). But this is the only L2 chord that introduces a double-sharp, in a module ("The Four Triad Types") whose objective is just to hear/build the four qualities. On a piano-style input the student selects pitch class 7, which the validator (pitch-class set comparison) accepts as the "G" key — so it *works*, but the staff/label may show F## with no scaffolding. Whether that is acceptable at L2 is a pedagogy/UX call, not a correctness defect. Flagging because B-augmented is the worst-case enharmonic the template can emit and a reviewer may want to drop B (or augmented-on-B) from the L2 range.
- **Correct version:** No theory correction needed — B aug = B D# F## is correct. Decision needed only on whether to expose it at L2.
- **Confidence:** high that the spelling is correct; the "should this be at L2" judgment is the open question.
- **Source/reasoning:** Engine output `B augmented => B D# F##`; tertian spelling rule (root/3rd/5th must use alternating letters B-D-F).

### Q2. Descending interval prompts accept only the ascending semitone count, with no audio for the non-ear variant
- **Location:** `templatesL2.ts` l2u7m1 interval template (`directions: ['ascending','descending']`); validator `validateIntervalId`; player `ExerciseRunner.tsx`/`ExercisePrompt.tsx`.
- **Type:** template / validation behaviour
- **Severity:** questionable
- **What it says now:** When `direction: 'descending'` is drawn, the prompt reads "Identify the interval from {root} going descending," but the accepted answer is the same `targetSemitones` value and the same label as the ascending case.
- **Concern:** Theoretically defensible — a descending P5 is still a P5, so labelling by absolute interval size is fine. But for the *non-ear* `interval_id` variant there is no audio and no second note rendered in text, so "going descending" is a pure instruction with no effect on the answer; it may read as if a different (inverted) interval is wanted. This is a clarity/validation-design concern, not a theory error. Worth a human decision on whether descending should be dropped from the text-only interval template.
- **Correct version:** n/a (no false statement); confirm intended behaviour.
- **Confidence:** medium (behaviour confirmed in code; "is this a problem" is a judgment call).
- **Source/reasoning:** `validateIntervalId` keys only on `config.targetSemitones`; `ExercisePrompt.tsx:55` and `ExerciseRunner.tsx:93` apply direction only to *audio* pitch, not to the accepted answer.

### Q3. Interval template at 6 semitones ("tritone") forces one enharmonic spelling and one label
- **Location:** `templatesL2.ts` l2u7m1 (includes 6) and l2u7m2 (includes 6); `INTERVAL_LABELS[6] = 'Tritone'`.
- **Type:** template / engine constant
- **Severity:** questionable
- **What it says now:** 6 semitones is labelled "Tritone." The l2u7m2 concept text correctly explains the tritone is "augmented fourth or diminished fifth ... same sound, different spelling." The generated note is spelled as a sharp (e.g. C->F#, F->B).
- **Concern:** Less severe than E1 because "Tritone" is a legitimate quality-neutral name and the module explicitly teaches it. Noting it only for completeness: the template cannot ask the student to *spell* the tritone as aug4 vs dim5 (it offers the single label "Tritone"), which is consistent with the lesson but means the aug4/dim5 distinction the concept text introduces is never exercised. No correction required.
- **Correct version:** n/a.
- **Confidence:** high (consistent with module text).
- **Source/reasoning:** Engine output and `INTERVAL_LABELS[6]='Tritone'`.

### Q4. `l2u7m1` interval-template hint lists augmented/diminished, which belong to the next module
- **Location:** `templatesL2.ts` l2u7m1 hint: "count semitones for the quality (major, minor, perfect, augmented, diminished)."
- **Type:** template (hint text)
- **Severity:** questionable
- **What it says now:** The hint lists augmented and diminished among the qualities to determine, but module l2u7m1 is the *Perfect/Major/Minor* module (augmented/diminished are the *next* module, l2u7m2). The l2u7m1 range `[1,2,3,4,5,7,8,9,10,11,12]` is exactly the P/M/m + octave set (it deliberately skips 6/tritone), so no augmented or diminished interval is actually generated here.
- **Concern:** The hint mentions qualities the module's own exercises never produce, which could confuse, but it is not a false theory statement (those qualities do exist). Borderline between nitpick and questionable; surfaced because it crosses the module boundary with l2u7m2.
- **Correct version:** Hint could be scoped to "major, minor, perfect" for l2u7m1. (Recommendation only.)
- **Confidence:** medium.
- **Source/reasoning:** Module objective vs hint wording; range analysis.

## NITPICKS

### N1. "Subdominant (below dominant)" — imprecise etymology in concept text
- **Location:** `curriculumL2.ts` l2u4m2 concept "The Seven Scale Degree Names": "4=Subdominant (below dominant)." Same phrasing in `glossary.ts` (`subdominant`) and `educationalContent.ts` (degree 4).
- **Type:** explanation
- **Severity:** nitpick
- **Concern:** The standard etymology is that the subdominant is the fifth *below the tonic* (mirror of the dominant a fifth above), not literally "below the dominant." The app's own exercise hint `l2u4m2e3` states the precise version correctly ("It sits a 5th below the tonic ... just as the dominant sits a 5th above"). The concept-text phrasing is a common simplification and the subdominant *is* a step below the dominant, so it is not false — just less precise than the hint two screens away. Minor internal inconsistency.
- **Confidence:** high (this is textbook etymology; the curriculum already states the precise form elsewhere).

### N2. Submediant gloss "often used in minor keys" is a weak/half-true characterization
- **Location:** `educationalContent.ts` degree 6 tooltip: "Submediant ... Adds color, often used in minor keys."
- **Type:** explanation
- **Severity:** nitpick
- **Concern:** The submediant (degree 6) is not specially "of minor keys"; it is a normal diatonic degree in both major and minor (it is the root of the relative minor from a major key, which may be the intent). The curriculumL2 l2u4m2 explanation itself is accurate ("Submediant — below the mediant, counting down"). This is peripheral content (a generic tooltip), included only because L2 teaches degree 6. Low impact.
- **Confidence:** medium (phrasing is vague rather than strictly wrong).

### N3. "Power chords" framing of the perfect 5th in an interval-quality exercise
- **Location:** `exercisesL2.ts` l2u7m1e1 hint: "This is a perfect 5th -- the interval found in power chords and the basis of the circle of fifths."
- **Type:** exercise (hint)
- **Severity:** nitpick
- **Concern:** Factually fine (power chords are root+5th; circle of fifths moves by P5). No correction. Listed only to confirm it was checked and is correct.
- **Confidence:** high.

## Coverage & limitations (what I did NOT fully verify)

- **Audio rendering of intervals/chords** was not executed (no playback in this environment). The *data and validation* path was verified; generated audio was not heard. The descending-interval audio (Q2) was read in code, not heard.
- **i18n overlays (pt/es)** for L2 were out of scope per instructions (audit covers English source `curriculumL2.ts`/`exercisesL2.ts`/`templatesL2.ts`). A translation that drifts from the English claim would be a separate finding set.
- **Exotic-scale engine bugs** reported by `verify-engine.ts` (23 critical `scale-pitch` findings on diminished/whole-tone/chromatic/altered/hungarian scales at theoretical roots Db/Gb/A#/Cb/Fb/E#/B#) are **real but out of L2 scope** — L2 only uses major, natural_minor, harmonic_minor, melodic_minor on natural roots, none of which are affected. Not counted in this report's totals; flagged here so they are not mistaken for "L2-clean implies engine-clean."
- **Seventh-chord diatonic tables** (`getDiatonicSeventhChords*`, `DIATONIC_SEVENTH_CHORD_QUALITIES`) were read and appear canon-correct, but L2 does not teach seventh chords (that is L3), so they were not exhaustively re-derived here.
- **The generator's `scale_degree_id` placeholder note** (`exerciseGenerator.ts` sets `note = root` as a placeholder, relying on the validator resolving by `correctDegree`) is correct for L2 because `validateScaleDegreeId` keys only on `correctDegree`, never on the stored note. The validator path was confirmed; not every UI rendering of the degree prompt was separately confirmed.
- **Did not** find any wrong key-signature claim, wrong minor-scale alteration, wrong triad quality, wrong inversion figure (5/3, 6/3->6, 6/4 all correct), or wrong diatonic-quality pattern (I-ii-iii-IV-V-vi-vii(dim) verified against the engine for C and against canon for all keys). Compound-meter content (6/8, 9/8, 12/8 groupings; simple-vs-compound division; 3/4-vs-6/8) and syncopation/triplet definitions are all correct. Relative/parallel key content and the three-minor-forms content are correct.
